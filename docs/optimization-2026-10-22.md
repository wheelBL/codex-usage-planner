# 易用性、性能与稳定性优化记录

基线：`743310b`。本轮围绕“打开面板 → 查看用量/历史 → 修改设置 → 故障恢复”改进现有实现，保留额度守恒、固定计划基准和跨采样核验规则。

## 问题与改动

| 范围 | 发现的问题 | 本轮改动 |
| --- | --- | --- |
| 请求恢复 | 主状态请求没有截止时间，15秒定时器可能叠加请求，较早响应可能覆盖保存或时间范围选择 | 统一有界请求；GET 8秒、POST 60秒，覆盖响应体读取；合并轮询，取消并忽略过期请求；清楚区分凭据失效、服务不可达与返回格式错误 |
| 设置反馈 | 保存没有进行中反馈；可以重复提交；所有错误被归入工作时段 | 未保存、保存中、成功、失败提示；提交期间锁定；休假日期和时段分别报错并定位输入；保留草稿直到保存成功 |
| 设置正确性 | 重复日期被最后一行静默覆盖；合法但不在预置列表中的工作日时区或休息日权重显示为空 | 重复/无效日期提交前校验；动态加入已保存值；工作时段最多8段；移除后恢复可预测的键盘焦点 |
| 历史可访问性 | 图表采样值依赖鼠标悬停 | 同窗口、同时间范围的最近50条采样表，带列标题、说明和可聚焦滚动区；完整历史仍可导出 |
| 计算开销 | 每次日历计算重复创建 Intl 格式器和解析午夜；预测复制整个90天历史后反转 | 有上限的格式器、午夜和时段缓存，按键逐项淘汰；预测倒序遍历历史尾部，保持原有连续样本规则 |
| 页面开销 | 未显示的计划也重复构建；后台浏览器继续刷新；重复绘制圆环 | 按可见页面渲染，计划未变时复用 DOM，复用格式器；隐藏普通网页暂停，显示时恢复；保留内嵌 Windows 托盘状态更新 |
| 并发持久化 | 多个设置/重算/刷新请求可能共用 `.tmp` 文件，计划在保存成功前已替换内存值 | 使用串行状态写入队列；失败不阻塞后续操作；网络读取在队列外；计划写盘成功后再发布 |
| 演示重启 | 每次启动重新设定模拟重置时间，被真实核验逻辑判断为可疑移动 | 未到期的演示周期复用已保存边界 |
| 回归稳定性 | 文件监听未关闭可使 Windows 测试不退出；Python 测试假定 POSIX 命令与目录 | 关闭监听，支持显式 Python 路径，修正本地 Windows 测试夹具；CI 设置 Python 并限制运行时间 |

## 性能实测

Windows / Node v24.14.0；129,600条模拟历史，5次预热、40次测量。每次执行相同的预算、趋势预测与用卡建议计算。数据与真实账户隔离。

| 指标 | 基线 | 优化后 |
| --- | ---: | ---: |
| 中位耗时 | 15.570 ms | 0.559 ms |
| P95耗时 | 31.321 ms | 0.871 ms |

中位计算耗时减少约96.4%。此结果不包含HTTP传输、完整历史JSON序列化、真实SSH通信或系统总CPU占用，不能等同整机性能提升。冷启动和不同硬件的结果可能不同。

重现：`npm run benchmark`；也可用 `node scripts/benchmark.mjs <另一份源码目录>` 对同一脚本比较两个版本。基线目录需要包含 `core.mjs`、`calendar.mjs`、`planner.mjs`、`advice.mjs` 和 `speed-sources.mjs`。

## 验证与边界

- Node完整回归：104/104通过，0跳过。新增覆盖请求合并、迟到成功/错误、响应体超时、取消与恢复、重复日期、缓存隔离、并发写入和演示重启。原有DST、额度守恒、固定计划、核验保护和RPC测试继续通过。
- 并发HTTP验证：8个设置写入全部返回成功，最终内存与磁盘一致；仅显示时区变更不重置计划基准。
- Python采集器以实际本地进程运行，验证UTF-8分片、截断和正文过滤；没有连接真实SSH主机。
- Windows原生外壳编译通过；真实WebView2执行9项交互检查：TPS请求、未保存提示、重复日期校验、错误焦点、保存锁、保存成功、计划导航、历史表格和恢复演示配置。
- 本轮原生截图：`native/tray-preview.png` 和 `native/plan-preview.png`，已打开检查；首页主要操作完整，计划图与表格可见。截图和原生测试输出按仓库规则保留在本机，不提交生成物。
- 通用浏览器自动化因无法可靠确认当前浏览器地址而停止。上述原生截图与交互结果来自仓库自己的演示自检；没有据此宣称完成全量读屏、窄窗口、系统通知或macOS原生验收。

后续仍值得单独评估：90天历史接口的分页/抽样、复杂多卡规划移出主事件循环，以及Windows原生服务异常退出后的自动重启。这些需要独立的正确性和恢复验证，本轮不修改其策略。
